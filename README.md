# Standalone backend

Express + TypeScript + Sequelize v6 + PostgreSQL, following the core patterns in `backend-v2-new` without Nx or shared packages. The `items` API is a small example; replace it with your own feature.

## Setup

1. Use Node.js 20.9 or newer and PostgreSQL 13 or newer.
2. Run `npm install`.
3. Copy `.env.example` to `.env` and set `DATABASE_URL` to your database.
4. Run `npm run redis:up` and `npm run redis:check`.
5. Run `npm run db:migrate`.
6. Run `npm run dev`.

`GET http://localhost:3000/api/health` checks the server. `GET /api/items`, `POST /api/items` with `{ "name": "Desk" }`, and `GET /api/items/<uuid>` demonstrate route → controller → service → repository → model. Item IDs are UUID v4 values generated by Sequelize; PostgreSQL also has a UUID default for direct inserts. The example item routes are public; add authentication and tenant checks before using them for real customer data.

Open **http://localhost:3000/api/docs/** for Swagger UI. It reads the same `openapi/openapi.yaml` used to generate TypeScript API types.

## Environment

`.env` is the single local source of environment values. `src/config/env.ts` validates those values for the running app. Sequelize CLI's `src/db/config.js` only reads the same `DATABASE_URL`; it does not define a second environment. Set real environment variables in production instead of committing `.env`.

Set `CORS_ORIGIN` to the exact origin of a browser frontend (for example, `http://localhost:5173`). Leave it empty when no cross-origin browser access is needed. Credentials are not enabled by default.

## Redis

`npm run redis:up` starts a dedicated Redis 8 container on `127.0.0.1:6384` with append-only persistence in a Docker volume. `npm run redis:down` stops it and retains its data. The default `REDIS_URL=redis://127.0.0.1:6384/0` matches this local container; set `REDIS_URL` to your authenticated Redis endpoint in production (`rediss://` for TLS). The local container is for development and is bound to localhost.

The server connects to Redis before listening and closes the shared client on shutdown. Startup fails if Redis cannot connect after bounded retries. Import `redis` from `src/common/redis.ts` when a feature needs Redis commands; use application-specific keys and explicit TTLs. `npm run redis:check` checks the actual shared client against Redis, including expiration and deletion. Redis is connected; item caching and Redis-backed rate limiting are not enabled by this setup.

Write the endpoint in `openapi/openapi.yaml` first, regenerate types, then add the route and implementation. Keep models in `src/db/models`, queries in `src/db/repositories`, and each controller or service focused on one operation. Do not manually edit generated types. The example list returns the newest 50 items; add pagination when the actual feature needs it.

## Shared file uploads and storage

Files use this app's shared middleware/helpers and connect directly to Wasabi (or another S3-compatible endpoint). No Asset Manager service is needed. Set `FILES_API_KEY` to a random key of at least 32 characters and configure `WASABI_BUCKET`, `WASABI_ACCESS_KEY_ID`, `WASABI_SECRET_ACCESS_KEY`, and region/endpoint in `.env`. File routes return 503 until configured; existing item/health routes still work. `FILES_KEY_PREFIX=standalone/` isolates this application's keys. Changing it makes old keys inaccessible to these helpers.

Send `X-Files-API-Key` on every file request. This key grants application-level access to all files under the configured prefix. It is server-to-server authentication: do not embed it in a public browser application. Integrate your login/session middleware and derive user/tenant key scope from authenticated context before exposing these routes to individual users.

| Endpoint | Input | Result |
| --- | --- | --- |
| `POST /api/files/upload?folder_name=documents` | Multipart files (`files`; other field names also supported) | File metadata array; `key` and `path` contain the storage key |
| `GET /api/files?keyPath=standalone/documents/...` | Storage key; optional `expiresIn` in seconds | `{ url, expiresIn }`, default 24 hours; download directly from that URL |
| `POST /api/files/presigned-url` | `{ "keyPath": { "name": "report.pdf", "type": "application/pdf" } }` | `{ url, keyPath, expiresIn, headers }`, default 3 hours |
| `DELETE /api/files` | `{ "keyPaths": ["standalone/documents/..."] }` | Deleted keys; 502 if storage reports partial deletion |

To upload using a presigned URL, PUT the raw file bytes to `data.url` with the returned `data.headers`; save `data.keyPath`. Configure your bucket CORS to allow PUT/GET and Content-Type from the browser's origin if using direct browser uploads. The API's CORS setting does not configure bucket CORS. Store keys in your own records, not expiring URLs. Both signing routes accept an optional `expiresIn` from 1 to 604800 seconds.

Multipart uploads allow 20 files per request, 25 MiB each. Names, extensions, declared types, and basic file signatures are checked; supported raster images are decoded and re-encoded without metadata. Temporary files are removed after success or failure. A failed batch attempts to delete earlier uploads; rollback failures are logged. Signature checks do not scan for malware or validate an Office/archive container's full contents. Presigned PUT uploads bypass server-side byte/size validation and metadata stripping; use multipart upload when these checks are needed. Downloads force attachment disposition and octet-stream content type.

Reuse `fileUploadWasabi(sizeInMiB, isPublic)` from `src/middleware/multer.middleware.ts` in future routes and read `req.uploadedFiles` for the completed metadata. Authenticate and validate the route before this middleware. `src/common/file-storage.ts` exposes `generatePresignedURL`, `generateUploadPresignedURL`, `fileUploadStreamData`, `uploadFileToWasabi`, `getFileFromWasabi`, `deleteFileFromWasabi`, `deleteMultipleFilesFromWasabi`, `deletePublicFileFromWasabi`, `generatePublicURL`, and key/type validation. These internal helpers require a trusted caller; the application API key is enforced by the HTTP router, not by each helper. Consume or destroy the Body stream returned by `getFileFromWasabi`.

Public helper uploads require the optional `WASABI_PUBLIC_*` settings and a bucket policy that permits public reads. The HTTP routes keep uploads private. CRM-specific folder rules, user/branch models, image resizing proxy, Statsig routing, and Asset Manager fallback are not part of this standalone app.
